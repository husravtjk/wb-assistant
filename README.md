# WB Assistant — локальный сервис для нескольких кабинетов Wildberries

Крутится на твоём ноутбуке. Раз в час тянет данные по всем магазинам через официальный
Seller API, складывает в SQLite, в 09:00 присылает сводку в Telegram и в течение дня
шлёт алерты. Панель для просмотра — на `http://127.0.0.1:8765`.

## Что делает

| Задача | Как часто | Источник |
|---|---|---|
| Заказы, продажи | каждый час | `/api/v1/supplier/orders`, `/sales` |
| Остатки, цены, реклама | каждые 6 часов | `/supplier/stocks`, `/api/v2/list/goods/filter`, `/adv/*` |
| Отзывы и вопросы | каждый час | `/api/v1/feedbacks`, `/api/v1/questions` |
| Прогноз OOS | расчёт | остаток ÷ средний темп заказов за 14 дней |
| Просадка спроса | расчёт | вчера против среднего за 7 дней |
| CPO и остаток бюджета кампаний | расчёт | расход ÷ заказы, бюджет ÷ вчерашний расход |
| Выкупы и возвраты | каждый час | `/supplier/sales`, saleID на `R` — возврат |
| Акции на 3 недели вперёд | каждые 6 часов | `/api/v1/calendar/promotions` |
| Маржа и точка безубыточности | расчёт | `costs.csv` + блок `economics` в конфиге |
| Кандидаты на разбор карточки | расчёт | просадки, возвраты, рейтинг, вопросы |

## Установка

1. Python 3.11+, при установке на Windows отметь «Add Python to PATH».
2. В папке проекта:

```
pip install -r requirements.txt
cp config.example.yaml config.yaml
```

3. Заполни `config.yaml`: токены магазинов, токен бота и chat_id.
4. Проверь связь: `python main.py check` — по каждому магазину должно быть `ok`.
5. Первый сбор: `python main.py collect` (несколько минут, статистика WB отдаёт
   один запрос в минуту).
6. Запуск: `python main.py`. Открой `http://127.0.0.1:8765`.

## Токены

Личный кабинет → Настройки → Доступ к API → создать токен. Нужны категории:
**Контент, Статистика, Аналитика, Продвижение, Цены и скидки, Вопросы и отзывы.**
Токен на каждый магазин отдельный. «Только на чтение» не ставь, если планируешь
автоответы на отзывы.

## Команды

```
python main.py           # сервер + планировщик
python main.py check     # проверить токены
python main.py collect   # разовый сбор данных
python main.py digest    # напечатать сводку в консоль, не отправляя
python main.py send      # собрать данные и отправить сводку в Telegram
python main.py costs     # загрузить себестоимость из costs.csv
python main.py audit     # список карточек на разбор + чек-лист
```

## Юнит-экономика

Скопируй `costs.example.csv` в `costs.csv` и заполни себестоимость по SKU:
упаковку, доставку до склада и прочие расходы на единицу. Затем `python main.py costs`.

Ставки комиссии, эквайринга, налога и логистики задаются в `config.yaml` → `economics`,
отдельно на каждый магазин или общим блоком `default`.

Минимальная цена считается так: логистика делится на процент выкупа, потому что за
невыкуп WB берёт доставку туда и обратно, и этот расход ложится на выкупленные единицы.

```
логистика_эфф = логистика / выкуп + обратная_логистика × (1 − выкуп) / выкуп
мин_цена      = (себестоимость + упаковка + доставка + хранение + логистика_эфф + CPO)
                ÷ (1 − комиссия − эквайринг − налог)
```

Процент выкупа берётся из твоих же данных за 30 дней, по каждому SKU отдельно;
если статистики мало — из `default_redemption`. CPO подтягивается из рекламной
статистики за 7 дней. Если цена уходит ниже минимальной, SKU попадает в сводку.

Акции проверяются тем же расчётом: если цена по акции ниже точки безубыточности,
предупреждение приходит **до старта акции**, пока товар ещё можно исключить.

## Чего сервис не делает

Разбор карточки автоматизировать нельзя — фото, инфографику и описание оценивает
человек. `python main.py audit` отбирает кандидатов (просадка заказов, высокий
процент возвратов, низкий рейтинг, много вопросов без ответа) и печатает чек-лист.

Причины возвратов в API не отдаются — виден только факт возврата. Причины ищи в
отзывах и вопросах по тем SKU, которые попали в список.

## Чтобы работало круглосуточно

Ноутбук не должен уходить в сон. Автозапуск на Windows: `Win+R` → `shell:startup` →
положить туда ярлык на `python C:\wb-assistant\main.py`.

Если ноутбук был выключен, планировщик догонит пропущенные задачи в пределах часа
(`misfire_grace_time`), а данные за прошлые дни всё равно подтянутся — API отдаёт
историю за 30 дней.

## Настройка порогов

В `config.yaml`, блок `thresholds`:

- `oos_days: 7` — при каком запасе дней бить тревогу
- `drop_pct: 30` — какое падение заказов считать просадкой
- `cpo_limit: 300` — выше какого CPO помечать кампанию красным
- `adv_budget_days: 2` — за сколько дней до обнуления бюджета предупреждать

## Если WB поменяет API

Хосты вынесены в `config.yaml` → `hosts`, пути к методам собраны в `wb/client.py`.
Актуальный список методов: dev.wildberries.ru. Для рекламной статистики в коде уже
стоит фолбэк: сначала пробуется `/adv/v3/fullstats`, при ошибке — `/adv/v2/fullstats`.

## Лимиты

WB жёстко ограничивает статистику — один запрос в минуту на метод. Лимиты заданы
в `config.yaml` → `rate_limits` и намеренно занижены. Поднимать не советую: при
превышении кабинет получает 429 и блокировку на час.

## Безопасность

`config.yaml` с токенами в репозиторий не попадает — он в `.gitignore`, плюс CI
падает, если найдёт в коде строку, похожую на токен WB. Если токен всё же утёк —
сначала отзови его в кабинете WB, потом чисти историю. Порядок именно такой.

## Чего здесь нет

Автоответы на отзывы, управление ставками и участие в акциях в этой версии не
включены намеренно — сначала неделя наблюдений за цифрами, потом автоматизация
действий. Методы в клиенте уже готовы (`feedback_answer`, `adv_budget`).
